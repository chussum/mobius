## 1. 배경

사용자는 Gemini 계정도 Claude, Codex 처럼 Mobius 에서 전환하기를 원했다. 처음에는 Gemini CLI(`gemini`)를
대상으로 조사했지만, 실측 결과 **개인 Google 계정으로 Gemini CLI 에 로그인하는 경로는 이미 막혀 있다.**

- `loadCodeAssist` 응답에서 무료 티어가 `ineligibleTiers` 로 내려오고, 사유는 `UNSUPPORTED_CLIENT`
  ("This client is no longer supported for Gemini Code Assist for individuals… migrate to the Antigravity
  suite")다. 실제 CLI 와 같은 클라이언트 메타데이터로 보내도 같다(gemini-cli 0.40.1, 2026-11-19).
- 외부 자료에서도 2026-06-18 에 개인 계정 로그인이 종료됐다고 확인된다. Gemini CLI 는 API 키와 유료
  Code Assist Standard/Enterprise 라이선스 계정에서만 계속 쓸 수 있다.

그래서 대상은 Google 이 대체 도구로 안내하는 **Antigravity CLI(`agy`)** 다.

## 2. 실측 사실 (agy 1.5.12, 2026-11-19)

| 항목 | 실측 결과 | 확인 방법 |
|---|---|---|
| 자격증명 위치 | 로그인 키체인 generic password, 서비스 `gemini`, 계정 `antigravity` | 속성만 조회(SecItemCopyMatching, 값 미요청). 로그인 시각과 생성 시각 일치 |
| 저장 방식 | zalando/go-keyring. macOS 에서 `/usr/bin/security` 를 실행해 읽고 쓴다 | 바이너리 심볼 `keyring.fallbackServiceProvider`, 저장 값 접두사 |
| 값 형식 | `go-keyring-base64:` + base64(JSON) | `security find-generic-password -w` 로 읽음. 승인창 없음 |
| JSON 구조 | `{"token":{"access_token","token_type","refresh_token","expiry"(RFC3339),"expires_in"},"auth_method":"consumer","id_token_email":"…"}` | 값은 가리고 키와 타입만 출력 |
| 신원 | `id_token_email` 이 값 안에 있다. 이메일만 따로 둔 평문 파일은 찾지 못했다 | `~/.gemini/antigravity-cli` 와 캐시 파일 확인 |
| 키체인 `mdat` 해상도 | 1초 | 속성 조회(설계 리뷰 1회차 Claude 리뷰어 실측) |
| 토큰 갱신 | `POST https://oauth2.googleapis.com/token`, client `1071006060591-tmhssin2…`, 바이너리 안의 desktop client secret(`GOCSPX-` 로 시작하는 문자열 세 개 중 하나)으로 성공 | client ID 3개 × secret 3개 조합 시험. 나머지 조합은 `invalid_client`/`unauthorized_client` |
| refresh 토큰 회전 | **없음.** 갱신 응답에 `refresh_token` 이 없다 | 같은 시험의 응답 키 |
| 사용량 조회 | `POST https://daily-cloudcode-pa.googleapis.com/v1internal:fetchAvailableModels`, 본문 `{}` 가능 | 200, 모델 15개 중 15개에 `quotaInfo` |
| 사용량 형식 | 모델별 `quotaInfo{remainingFraction, resetTime}`. `tab_*` 모델은 `resetTime` 없이 `remainingFraction` 만 온다 | 응답에서 모델 ID, 표시명, quotaInfo 만 추림 |
| User-Agent | **필수.** 없거나 Python 기본 UA 면 403 `The caller does not have permission`, `antigravity-cli/1.5.12` 면 200 | 같은 토큰으로 UA 유무만 바꿔 비교 |
| `retrieveUserQuota` | 무료 계정은 403 `SUBSCRIPTION_REQUIRED` | 사용하지 않는다 |
| 로그인 명령 | `agy login` 같은 하위 명령이 없다. 대화형 세션 안에서 로그인한다 | `agy --help` |
| 설치 형태 | Homebrew cask. `/opt/homebrew/bin/agy` 는 실제 바이너리(`…/Caskroom/antigravity-cli/<ver>/antigravity`)를 `exec` 하는 bash 래퍼다 | 래퍼 내용 확인 |

실측 스크립트는 저장소에 넣지 않았고, 토큰, 이메일, 프로젝트 ID 는 출력하지 않았다.

### 2.1 두 계정 E2E 결과 (2026-11-19 22:20~22:50)

로그아웃·재로그인과 키체인 값 교체로 확인했다. 키체인 항목의 수정 시각, 이메일·토큰 해시,
`credential-user-scope` 를 10초마다 기록했다.

**계정 주의.** agy 의 로그아웃은 토큰을 폐기하지 않는다(아래 표). 시험용으로 로그인했던 계정의 Antigravity 접근
권한은 Google 쪽에 남으므로, 정리하려면 Google 계정 보안 설정에서 회수한다.

| 확인 항목 | 결과 |
|---|---|
| `credential-user-scope` 가 계정마다 다른가 | **다르다(추정).** 같은 프로세스 안에서 다시 로그인했을 때는 그대로였지만, 다른 계정이 키체인에 있는 상태에서 새 agy 프로세스가 시작되자 곧바로 다른 값으로 바뀌었다. agy 가 시작할 때 직접 다시 쓰는 값으로 보이므로 Mobius 는 건드리지 않는다 |
| 로그아웃(`/logout`)이 토큰을 폐기하는가 | **폐기하지 않는다.** 키체인 항목만 지운다 |
| 다시 로그인하면 예전 스냅샷이 무효가 되는가 | **되지 않는다.** 재로그인은 새 refresh 토큰을 발급하지만 예전 refresh 토큰도 계속 유효하다 |
| 실행 중인 세션이 키체인 교체를 따라가는가 | **따라가지 않는다.** 키체인을 바꾼 뒤 그 세션의 요청은 원래 계정의 사용량으로 잡혔다. codex 처럼 토큰을 메모리에 들고 있다 |
| 세션 종료 때 키체인을 되돌려 쓰는가 | 쓰지 않았다(수정 시각 변화 없음) |
| 사용량 버킷 | Gemini 계열 모델 10개가 하나의 5시간 버킷을 공유한다(요청 뒤 모두 같은 remainingFraction 과 resetTime). 사용 전 resetTime 이 7일로 보이던 `gemini-3.8-flash-tiered` 도 사용 뒤에는 이 버킷에 들어갔다 |

아직 확인하지 못한 것:
1. **agy 가 갱신한 access 토큰을 키체인에 다시 쓰는가.** 다시 쓴다면 이전 계정 세션이 갱신 시점에 키체인을
   되돌리는 클로버가 생긴다(4.7 「왕복 차단」).
2. **새로 시작한 세션이 키체인의 계정을 쓰는가.** 개인 계정 두 개로 확인한다(7절).
3. **소진 응답 형식.** remainingFraction 이 0 으로 오는지, proto3 JSON 규칙대로 필드가 빠지는지, 소진 뒤 resetTime 이
   고정되는지 관찰하지 못했다(4.3 「빠진 값」).
4. UA 값 조건: `antigravity-cli/<ver>` 형식이어야 하는지, 비어 있지만 않으면 되는지.

## 3. 범위

넣는 것:
- `Provider.antigravity` (표시명 "Antigravity").
- 계정 등록: Codex 와 같은 adopt 방식. 사용자가 agy 에서 로그인하면 앱 틱이 감지해 등록한다.
- 수동 전환: 저장해 둔 키체인 값을 라이브 키체인 항목에 쓴다.
- 사용량 게이지: 팝오버를 열 때 `fetchAvailableModels` 로 조회한다. 활성·비활성 계정 모두 같은 경로다.
- 자동 전환(옵트인, 기본 꺼짐): 4.7.
- CLI: `list`, `status`, `switch`, `auto --provider antigravity`. `capture` 는 지원하지 않는다(등록은 adopt).
- 다운그레이드 호환(4.4).

넣지 않는 것:
- 로그 기반 소진 감지. 로그 줄에는 계정이 없고 형식도 관찰하지 못했다. 소진 판정은 사용량 API 로만 한다.
- Gemini CLI(`gemini`) 지원. 개인 계정 로그인이 막혀 있다.
- 앱 안 로그인 흐름(LoginFlow). agy 에 비대화형 로그인 명령이 없다.
- 재로그인 필요(`needsReauth`) 자동 감지. 갱신이 `invalid_grant` 여도 게이지만 비운다(4.3).
- accounts.json 동시 저장 경합의 근본 해결(앱과 CLI 가 각자 메모리의 전체 목록을 저장하는 문제). 이번 변경 전부터 있는
  결함이고 CLAUDE.md 「후속 후보: accounts.json 파일 락」으로 남긴다. 다만 Antigravity 가 이 경합에 새 쓰기 경로
  (agy 대사·adopt·복원·자동 전환 기록)를 더하므로(2·3회차 Codex P1-1), **Antigravity 프로필과 Antigravity 풀 상태를
  바꾸는 모든 저장**은 저장 직전에 디스크의 파일을 다시 읽어 그 변경만 얹어 저장한다(`AccountStore.mutateFresh`).
  소진 기록, 활성 전환, 자동 전환 설정이 모두 여기에 든다. 창을 밀리초 단위로 줄일 뿐 없애지는 못한다.
  다시 읽은 파일이 구버전이 저장한 것(`extraProviderAccounts` 키 없음)이면 4.4-4 의 복원 함수 하나를 그대로 쓴다:
  Claude·Codex 는 디스크 값, Antigravity 프로필과 순서는 메모리 값, Antigravity 자동 전환 설정은 꺼짐, 활성은 라이브로
  reconcile. 이 함수는 앱 시작, `reload`, `mutateFresh`, CLI `makeContext` 가 모두 같은 순서로 부른다(6회차 Codex P1-1).

## 4. 설계

### 4.1 어댑터 `AntigravityConfigIO: ProviderConfigIO`

- secret data 는 **키체인 값 문자열의 바이트 그대로**(`go-keyring-base64:…`)다. Codex 가 `auth.json` 원본 바이트를
  통째로 저장하는 것과 같은 원칙이다.
- **형태 검증(`recognizesSecret`)**: 접두사가 `go-keyring-base64:` 이고, base64 가 디코드되고, JSON 의
  `token.access_token`·`token.refresh_token`·`token.token_type` 이 비어 있지 않은 문자열이고, `token.expiry` 가
  RFC3339 로 해석되는 문자열이며(`expires_in` 은 있으면 숫자), `id_token_email` 이 `@` 를 포함한 문자열이고,
  `auth_method` 가 `consumer` 다. 실측한 형태만 받는다. 다른 값이 나오면 등록하지 않고 실측 뒤에 넓힌다. 같은 검증을
  저장, 조회, 설치 모두에 쓴다. 바이트 해석이 실패하면 그 값은 없는 것으로 다루고, 따로 읽은 이메일로 대신하지 않는다.
- **신원은 같은 바이트에서 꺼낸다.** 새 프로토콜 메서드 `email(fromSecret:)` 을 두고, agy 와 Codex 는 바이트에서
  이메일을 꺼내며 Claude 는 nil(지금처럼 `~/.claude.json` 으로 대조)을 돌려준다. Switcher 의 저장·설치 경로는 이
  메서드가 값을 주면 **저장하거나 설치하는 바이트의 이메일**과 프로필 이메일이 같을 때만 진행한다.
  - 되저장(`resaveLiveIntoMatchingProfile`), adopt, reconcile, 활성 스냅샷 갱신: 읽은 바이트의 이메일로 프로필을 고른다.
    이메일을 따로 읽은 값과 짝짓지 않는다(키체인 값과 이메일을 따로 읽는 틈. 실패 기록 1·2 와 같은 종류).
  - 전환(`switchTo`): 설치할 스냅샷 바이트의 이메일이 대상 프로필 이메일과 다르면 throw 한다.
- **agy 항목의 값 읽기·쓰기·삭제는 모두 `security` CLI 만 쓰고, 각각 5초 제한 시간을 둔다.** 새 전용 클라이언트
  `CLIKeychain`(`KeychainClient` 를 따르되 네이티브로 떨어지지 않는다)을 agy 어댑터에만 주입한다.
  - 지금 `SystemKeychain` 은 쓰기가 두 CLI 경로 모두 실패하면 `SecItemUpdate`/`SecItemAdd` 로, 읽기가 CLI 오류면
    `SecItemCopyMatching` 으로 떨어진다. agy 항목에 네이티브 쓰기가 일어나면 파티션이 Mobius 의 cdhash 로 재도장되어
    agy 의 `security` 읽기가 암호창을 띄운다(실패 기록 12). 네이티브 읽기는 제한 시간 없이 암호형 승인창을 기다린다.
  - 지금 CLI 경로는 프로세스 종료를 제한 없이 기다리므로, 승인 대기에서 멈추면 첫 어댑터인 agy 가 Claude·Codex 대사와
    CLI 출력까지 멈춘다. 5초가 지나면 프로세스를 끝내고 실패로 돌려준다(4.6 의 오류 격리로 넘어간다).
  - **시간이 넘은 쓰기는 결과를 모른다.** 그때는 라이브 상태를 "모름"으로 두고, 라이브 값을 읽어 확인할 때까지 agy 항목에
    다른 쓰기와 Antigravity 자동 전환을 하지 않는다. "모름"인 동안은 4.2 의 `mdat` 비교와 상관없이 값을 읽어 확인하고
    (성공하면 해제), 그동안 카드에 "계정 상태 확인 중"을 보인다. 조용히 꺼진 채로 남지 않게 한다(4회차 Claude P2-2).
    확인 읽기는 1분 뒤 처음 시도하고, 실패하거나 시간을 넘기면 간격을 5분, 15분으로 늘린다. 시간 초과는 승인창이 떠 있다는
    뜻일 수 있으므로 같은 간격으로 반복해 승인창을 쌓지 않는다(5회차 Claude P2-1, 실패 기록 4 와 같은 종류).
  - **전송 방식.** 쓰기는 기존 `writeViaSecurityCLI` 와 같이 `security -i` 의 표준 입력으로 비밀을 넘기고, 같은 길이
    가드(명령 한 줄 4,096바이트 미만)를 지난 값만 이 경로로 보낸다. `-i` 는 한 줄 제한을 넘는 명령을 잘라서 쓰고 종료 코드
    1 을 낸다는 실측이 코드 주석에 있다(6회차 Codex P1-5). 가드를 넘는 값은 쓰지 않고 오류로 끝낸다(agy 값은 실측 약
    800바이트). 쓰기가 시간 초과가 아닌 이유로 실패해도 항목이 바뀌지 않았다고 가정하지 않고 "모름" 처리로 보내 값을 읽어
    확인한다.
  - 테스트는 CLI 가 실패하거나 시간을 넘길 때 네이티브 키체인 호출이 0회임을 단언한다.
  - 값 읽기 경로는 하나다. 4.2 의 변화 감지, "모름" 확인 읽기, 4.7 의 작업 시작 확인과 최종 재확인 모두 이
    클라이언트의 같은 읽기 함수(제한 시간 5초)를 쓴다.
- 삭제는 하지 않는다(로그아웃을 흉내 내지 않고, 롤백도 하지 않는다. 4.5).
- Claude·Codex 의 키체인 경로(`SystemKeychain`)는 바꾸지 않는다.
- `-w` 읽기의 16진수 변환 함정은 이 값에 해당하지 않는다(base64 는 출력 가능한 ASCII 다). 기존 hex 판별 경로가 처리한다.
- `readStableLiveSecretData`: 0.7초 간격으로 두 번 읽어 같을 때만 인정한다.

### 4.2 틱마다 키체인 값을 읽지 않기 (실패 기록 3, 3b)

`liveEmail()` 은 틱마다 불린다. agy 는 이메일이 키체인 값 안에만 있으므로 다음 순서로 판단한다.

1. 키체인 항목의 **속성만** 조회한다(SecItemCopyMatching, `kSecReturnAttributes`, 값 미요청, 인증 UI 금지).
   `errSecInteractionNotAllowed`(키체인 잠김 등)는 "변화 없음"으로 처리한다. 항목이 없으면 로그아웃 상태다.
2. 수정 시각(`mdat`)이 직전 판단 때와 같으면 캐시한 이메일을 돌려준다.
3. 다르면 값을 읽어 캐시를 갱신한다. Mobius 자신이 쓴 뒤에는 캐시를 비운다. 값 읽기가 실패하면 그 `mdat` 에 대해서는
   5분 뒤에 다시 시도한다(15초마다 같은 실패를 되풀이하지 않는다. 4회차 Claude P2-3).

`mdat` 와 캐시한 이메일은 "값을 다시 읽을지"를 정하는 데만 쓴다. 저장과 설치의 신원 대조는 4.1 대로 바이트에서
꺼낸 이메일로 한다. 1초 해상도 때문에 같은 초 안의 두 번 쓰기를 놓쳐도, 저장 쪽에서 바이트 이메일로 다시
대조하므로 다른 계정의 값이 저장되지 않는다.

**활성 계정 스냅샷 갱신.** 3단계에서 값을 읽었고 그 바이트의 이메일이 활성 Antigravity 프로필과 같으면 그
프로필의 스냅샷으로 저장한다(네트워크 0). 같은 이메일로 다시 로그인해 받은 새 refresh 토큰이 저장되지 않은 채
남는 일을 막는다.

### 4.3 사용량 게이지

- 새 `AntigravityUsageFetcher`. 자격증명이 실리는 요청이므로 **ephemeral 세션**을 쓰고(실패 기록 18), UA 는 세션
  `httpAdditionalHeaders` 로 싣는다(실패 기록 14). UA 의 버전은 설치된 agy 의 버전(Caskroom 경로나
  `agy --version`, 한 번만)을 쓰고 못 얻으면 실측 버전 `1.5.12` 를 쓴다. 전송 경로는 주입하고, 테스트는 fetch 가 그
  경로를 실제로 탔는지 단언한다.
- **토큰 갱신.** access 토큰이 만료됐으면 **메모리에서만** 갱신한 토큰으로 조회한다. refresh 토큰이 회전하지 않으므로
  저장본을 바꾸지 않고, Codex 의 회전본 원자 저장이나 전환 경합 게이트가 필요 없다. 활성 계정도 같은 이유로 agy
  세션을 망가뜨리지 않는다.
  - client ID 는 상수로 둔다(공개 식별자). **client secret 은 저장소에 넣지 않는다**(0절). 설치된 agy 바이너리에서
    `GOCSPX-` 로 시작하는 문자열 후보를 실행 중에 찾고, 처음 갱신할 때 후보를 차례로 시도해 성공한 값을 메모리에
    둔다. 실패한 후보는 `invalid_client` 로 끝나 계정에 영향이 없다. 바이너리 경로는 `ToolInventory.locateCLI("agy")`
    로 찾은 뒤 래퍼 스크립트면 `exec` 대상을 따라간다(실패 기록 15). 사용자의 `~/bin/agy` 같은 다른 래퍼도 같은
    방식으로 따라간다.
  - secret 을 찾지 못하면 갱신하지 않는다. access 토큰이 만료된 계정의 게이지는 마지막 값을 흐리게 보이고(기존
    stale 표시), 자동 전환의 후보 확인은 "확인 불가"로 처리한다(4.7).
  - 갱신 결과가 `invalid_grant` 면 게이지만 비우고 계정별로 긴 백오프를 둔다. `needsReauth` 와 엔진은 건드리지 않는다
    (Codex 게이지 방화벽과 같은 계약).
- 조회 주기: 팝오버를 열 때만, 캐시 4분, 실패 시 계정당 재시도 쿨다운. 자동 전환을 켰을 때의 폴링은 4.7 이다.
- **모델 해석 규칙.**
  - `quotaInfo` 가 없거나 `resetTime` 이 없는 모델(`tab_*`)은 제외한다.
  - `resetTime` 은 있는데 `remainingFraction` 이 없으면 **값 모름**이다. 게이지에는 0% 로 보이되 "확인 안 됨"을
    붙이고, 자동 전환 판정에는 쓰지 않는다. proto3 JSON 은 기본값 0 을 출력하지 않으므로 소진 상태가 이 모양으로 올
    수 있지만(추정, 2.1 미확인 3), 확인 전에는 키체인 쓰기의 근거로 삼지 않는다. 이 모양을 처음 보면 로그에 한 줄
    남겨 실측 근거를 모은다. 사용 전 모델은 1 이 명시적으로 온다(실측).
  - remainingFraction 이 1 이면 "아직 사용 안 함"이다. 이때 resetTime 은 요청 시각 + 창 길이라 표시에 쓰지 않는다.
  - 시각 해석은 소수부가 있는 RFC3339 와 없는 RFC3339 를 모두 받는다(`ISO8601DateFormatter` 하나로는 둘 다 읽지
    못한다. 3회차 리뷰 확인). 키체인 값의 `token.expiry` 도 같은 함수로 읽는다.
- **버킷 묶기와 라벨(표시용).** 같은 응답 안에서 `(remainingFraction, resetTime)` 이 같은 모델을 한 버킷으로 묶는다.
  라벨은 버킷 안 모델 ID 의 계열이다: `gemini-` 로 시작하면 "Gemini", `claude-` 면 "Claude", 그 밖은 첫 모델의
  표시명이다. 같은 라벨이 둘 이상이면 뒤에 번호를 붙여 줄 ID 가 겹치지 않게 한다(카드는 라벨을 줄 ID 로 쓴다).
  사용 전 모델은 묶지 않고 같은 계열의 버킷 줄이 없을 때만 "아직 사용 안 함" 줄 하나로 보인다.
  창 길이(5시간/주간)는 "지금부터 resetTime 까지 남은 시간"으로 정하지 않는다(리셋 직전 오분류, Codex 슬롯 오분류와
  같은 종류). 표시에 창 길이가 필요하지 않으므로 계산하지 않는다.
- 저장: `UsageSnapshot.scopedLimits` 에 버킷 줄을 담는다. "아직 사용 안 함"은 `resetsAt == nil` 로 나타내고 카드가
  Antigravity 계정일 때 그 문구를 보인다. 기존 Codable 구조에 필드를 더하지 않으므로 `usageCacheV1` 호환이 유지된다.
- **판정용 기준값.** 버킷 묶기는 표시에만 쓴다. 소진 판정(4.7)은 **계정 ID × 모델 ID** 단위로 한다. 버킷 키
  `(remainingFraction, resetTime)` 은 값이 바뀌면 키도 바뀌므로 같은 버킷을 이어 볼 수 없다.

### 4.4 다운그레이드 호환

현재 `AccountProfile.init(from:)` 은 `provider` 값이 모르는 문자열이면 throw 한다. 그러면 `AccountsFile` 전체
디코드가 실패하고 `AccountStore.init` 은 원본을 `accounts.corrupt.json` 으로 백업한 뒤 throw 한다. 앱은 빈 스토어로
시작하고, 다음 reconcile 이 라이브 계정만 저장하며 **Claude·Codex 계정 목록까지 덮어쓴다**(실패 기록 13).
이미 배포된 바이너리는 고칠 수 없으므로, 새 버전은 **구버전이 읽는 자리에 모르는 provider 를 쓰지 않는다.**

1. `accounts` 배열에는 claude, codex 만 쓴다. 그 밖의 provider 계정은 새 키 `extraProviderAccounts` 에 쓴다.
   구버전의 `AccountsFile.init(from:)` 은 모르는 키를 무시한다(설계 리뷰 1회차에서 0.5.3 디코더로 확인. upstream
   v0.5.5 위로 rebase 한 뒤 v0.5.4 디코더로도 확인 — v0.5.4·v0.5.5 도 모르는 provider 항목에서 throw 한다).
2. 프로바이더 맵(`activeByProvider` 등)은 이미 모르는 키를 건너뛰므로 `antigravity` 키를 그대로 쓴다.
3. 두 배열 모두 항목 단위로 디코드한다. 모르는 provider 항목은 원본 JSON 을 보존해 다시 쓴다. 프로바이더 맵의
   모르는 키도 원본 값을 보존한다. 아는 provider 항목의 값 손상은 지금처럼 throw 해서 corrupt 백업 경로를 살린다.
4. **구버전 저장 뒤 복원.** 새 버전은 `extraProviderAccounts` 키를 항상 쓴다(비어 있어도). 이 키가 없는 파일은
   구버전이 저장한 것이다. 그런 파일을 읽었을 때만 `secrets/` 의 프로필 없는 파일 가운데 Antigravity 어댑터가
   알아보는 것을 프로필로 복원한다.
   - UUID 는 파일 이름을 그대로 쓰고 `*.bak` 은 건너뛴다. 같은 (provider, 이메일) 프로필이 이미 있으면 복원하지 않는다.
   - 이 판정은 `AccountStore` 를 읽는 모든 자리(앱 시작, `reload`, CLI `makeContext`)가 같은 함수로 한다.
   - 키가 있는 파일에서 보이는 고아 secret 은 삭제 실패의 흔적이므로 복원하지 않는다(삭제한 계정이 되살아나지 않게).
   - 구버전 저장 뒤에도 삭제 사실이 남도록, Antigravity 계정을 지울 때는 secret 을 지우기 **전에**
     `secrets/<uuid>.removed` 표시 파일을 쓴다. 복원은 이 표시가 있는 UUID 를 건너뛴다. 구버전은 이 파일을 읽지 않는다.
   - CLI `list`·`status` 는 복원 결과를 보여 주기만 하고 파일에 저장하지 않는다. 저장은 앱과 CLI 의 변경 명령만 한다.
   - 활성 상태는 라이브 키체인 이메일로 reconcile 한다. **Antigravity 풀 설정(자동 전환 켬/끔)은 메모리 값을 되살리지
     않고 기본값(꺼짐)으로 둔다.** 사용자가 끈 자동 전환이 다시 켜지는 일을 막는다(5회차 Codex P1-5). 사용자에게
     "이전 버전이 계정 목록을 저장해 Antigravity 설정을 되돌렸어요"를 한 번 알린다.
   - 앱이 떠 있는 동안 복원하는 경우(`reload`, `mutateFresh`)에는 메모리에 있던 Antigravity 프로필 순서를 쓴다
     (primary 가 바뀌지 않게. 4회차 Claude P2-5). 앱 시작 때는 메모리 값이 없으므로 secret 파일의 수정 시각 순으로 둔다.
   - 앱의 `reload()`(변경 통지로 파일을 다시 읽는 경로)도 이 함수를 지나간다(5회차 Claude P2-2).
5. **보장 범위.** 프로바이더별 풀(v2 형식)을 읽는 버전부터 보장한다. 정확한 최소 버전은 구현 때 태그로 확인해
   README 와 릴리스 노트에 적는다. 그보다 오래된 버전으로 내려가는 경우는 CLAUDE.md 「혼합 버전 주의」와 같이
   지원하지 않는다고 적는다.
6. 마이그레이션 테스트(`MobiusCoreTests`): (a) 0.5.3 형식 파일을 새 버전이 읽는다, (b) 새 버전이 쓴 파일을 0.5.3 의
   `AccountsFile` 디코더(테스트 안에 고정 사본)가 읽고 Claude·Codex 의 ID, 순서, 활성, 풀 구분이 그대로다,
   (c) (b) 를 다시 인코드한 파일에서 새 버전이 secret 으로 계정을 복원하고 중복이 생기지 않는다,
   (d) 모르는 provider 항목과 맵 키가 왕복 뒤에도 남는다, (e) 최신 릴리스(v0.5.4 고정 사본 — v0.5.5 와 같은 모델)의
   디코더가 새 파일을 읽고 같은 이메일의 두 조직이 `organizationUuid` 로 구분된 채 남으며, 그 판이 다시 저장한 파일을
   새 버전이 읽고 다시 저장해도 `organizationUuid` 가 남는다. v0.5.4 보다 오래된 판이 저장하면 이 필드는 빠지고, 새
   버전이 그 파일을 읽을 때마다 구버전 저장 뒤 복원 함수가 upstream 의 `backfillOrganizationUUIDs` 와 같은 규칙으로 저장
   스냅샷에서 채운다(스냅샷 파일이 없으면 메모리의 같은 id 값). 시작 때만 채우면 떠 있는 동안의 다시 읽기와 시작 실패
   뒤 복구가 조직을 잃는다(병합 리뷰 Codex P1-1·Claude P2-1). 앱은 시작 실패 뒤 다시 읽기에 성공하면 heal·backfill·등급
   갱신을 한 번 더 돌린다.

### 4.5 전환

- `Switcher.switchTo` 를 쓴다. 쓰기 대상은 키체인 항목 하나다. `credential-user-scope` 는 agy 가 시작할 때 스스로
  다시 쓰는 값으로 보이므로 건드리지 않는다(2.1).
- 설치할 바이트의 이메일이 대상 프로필과 다르면 throw 한다(4.1).
- **Antigravity 는 키체인 쓰기 뒤에 키체인을 되돌리지 않는다.** `security` CLI 로는 "지금 값 비교"와 "되돌리기"를
  원자적으로 묶을 수 없어서, 되돌리는 사이에 끝난 새 agy 로그인을 덮거나 지울 수 있다(4·5회차 Codex P1-5·P1-6).
  - 키체인 쓰기가 실패하면(시간 초과가 아닌 실패) `add-generic-password -U` 는 항목을 바꾸지 않으므로 되돌릴 것이 없다.
  - 키체인 쓰기는 성공했는데 `setActive` 저장이 실패하면, 키체인은 그대로 두고 메모리의 활성 값을 되돌린 뒤 "agy 는
    <계정>으로 바뀌었지만 계정 목록 저장에 실패했어요"를 알린다. 다음 reconcile 이 라이브를 따라 활성을 맞춘다.
  - 시간 초과는 4.1 의 "모름" 처리다.
  - `setActive` 는 저장이 실패하면 메모리의 활성 값도 되돌린다(지금은 메모리를 먼저 바꾼 채 남는다).
  - 파일 저장의 커밋 시점은 원자 교체(rename)다. 그 뒤의 권한 설정 실패는 저장 실패로 보지 않고 로그만 남긴다.
  - Claude·Codex 의 기존 롤백 동작은 바꾸지 않는다.
  - 테스트: "키체인 쓰기 성공 + 저장 실패"에서 키체인 쓰기·삭제 호출이 더 없고 메모리 활성이 되돌아가는지.
- 자동 전환이 부르는 `switchTo` 는 4.7 「비동기 경합」의 기대값을 넘기고, 라이브 쓰기 직전에 다시 확인한다.
- 실행 중인 세션은 토큰을 메모리에 들고 있으므로(2.1), 전환 알림은 "실행 중인 agy 세션은 다시 시작해야 새 계정이
  적용돼요"로 안내한다. 토글 도움말과 README 「알아두면 좋은 제약」에도 같은 내용을 적는다.
- 사용자가 agy 에서 로그아웃하고 다른 계정으로 로그인하는 흐름이 그대로 "계정 추가" 경로다(저장 스냅샷은 로그아웃과
  재로그인 뒤에도 유효하다. 2.1).
- 수동 전환의 핀은 지금처럼 세운다. Antigravity 에서는 핀이 쓰던 버킷 소진 전환을 막지 않는다(4.7).

### 4.6 프로바이더 오류 격리

어댑터는 rawValue 순으로 돌기 때문에 `antigravity` 가 Claude·Codex 보다 먼저 돈다. 지금 `reconcile`·adopt 루프는 첫
오류에서 끝나므로, agy 키체인 오류 하나가 Claude·Codex 대사를 멈추고 CLI `list`·`status` 를 실패시킨다.

- Switcher 의 전 프로바이더 루프(`reconcile`, `adoptLiveAccountIfUnregistered`, `healMisassignedProviders`)는
  프로바이더별로 오류를 잡아 모으고 다음 프로바이더를 계속 돈다. 결과로 실패한 프로바이더 목록을 돌려준다.
- 앱은 그 틱에 대사가 실패한 풀의 엔진 `onTick` 과 자동 쓰기(전환)를 건너뛴다(오래된 활성 표시로 판단하지 않는다).
  로그 hit 과 임계값 이벤트도 같은 진입점(`apply`)에서 막는다. 소진 **기록**은 라이브 쓰기가 아니므로 막지 않는다
  (2026-11-20, 코드 리뷰 1회차 반영 때 정함).
- Antigravity 대사는 공통 틱이 기다리지 않는 별도 작업에서 한다. agy 키체인 시간 초과가 Claude·Codex 의 대사 주기를
  늦추지 않게 한다(코드 리뷰 1회차 Codex P2-1).
- CLI 는 실패한 풀을 오류 한 줄로 보이고 나머지 풀은 그대로 출력한다.
- 오류를 던지지 않고 멈추는 경우(승인 대기)는 4.1 의 값 읽기 제한 시간이 막는다. 테스트는 응답하지 않는 어댑터를
  주입해 나머지 풀이 처리되는지 확인한다.

### 4.7 자동 전환 (옵트인)

**규칙 한 줄.** 지금 쓰던 모델(들)이 명시적인 0 이 되면, 그 모델 모두에 명시적인 여유가 확인된 다음 계정으로 옮긴다.
계정 전체 소진 판정과 리셋 시각 기반 primary 자동 복귀는 두지 않는다(0절, 2026-11-20 작성자 결정. 설계 리뷰 5회차까지
남은 P1 이 대부분 이 두 규칙에서 나왔다).

**신호.** 소진 판정은 계정별 토큰으로 조회한 `fetchAvailableModels` 응답만으로 한다. 귀속이 구조적으로 정확하다.

**폴링 조건.** 아래를 모두 만족할 때만 5분마다 **활성 Antigravity 계정 하나**를 조회한다.
1. Antigravity 풀의 자동 전환이 켜져 있다. 기본값은 **꺼짐**이다(켜면 폴링이 생기는 기능은 옵트인으로 둔다는
   CLAUDE.md 「임계값 선제 알림/전환」 선례). `AccountsFile.isAutoSwitchEnabled` 의 "기록 없는 풀은 켬" 규칙에
   프로바이더별 기본값을 더한다(Claude·Codex 는 지금처럼 켬). 구 전역 키 해석도 같은 기본값을 따른다.
2. 최근 30분 안에 agy 를 썼다. 신호는 `~/.gemini/antigravity-cli/history.jsonl` 의 수정 시각이다(사용자 입력 때만
   쓰인다). `cli.log` 는 유휴 상태에서도 주기적으로 쓰이므로 쓰지 않는다.
3. Antigravity 전용 서킷 브레이커(`UsagePollBreaker` 와 같은 규칙, 카운터는 프로바이더별)가 열려 있지 않다.

**작업 시작 확인.** 폴이나 후보 확인을 시작할 때, 저장된 활성 Antigravity 프로필의 이메일과 라이브 키체인 바이트의
이메일이 같지 않으면(외부 로그인 직후, 로그아웃 상태 등) 이번 작업을 하지 않는다. 다음 reconcile 이 상태를 맞춘
뒤에 한다(5회차 Codex P1-4).

**기준값과 활성 세대.**
- `AccountStore` 는 프로바이더별 **활성 세대 번호**(메모리)를 둔다. 활성 값이 바뀔 때마다 1 늘린다. 자기 `setActive`,
  reconcile, 디스크에서 다시 읽은 파일의 활성 값이나 **활성 리비전**(아래)이 메모리와 다를 때 모두 포함한다. 같은
  계정으로 돌아온 왕복(앱이든 CLI 든)도 세대를 바꾼다. **라이브 키체인 바이트의 해시가 바뀔 때도**(같은 이메일로 다시
  로그인, 로그아웃 뒤 재로그인) 세대를 늘린다. 이전 로그인에서 본 값과 새 로그인의 값을 비교하지 않기 위해서다(6회차
  Codex P1-2). 해시는 4.2 에서 값을 읽을 때마다 비교한다.
- 계정 ID × 모델 ID 마다 마지막으로 본 remainingFraction 과 그때의 세대 번호를 메모리에 둔다.
- **전이는 같은 세대 안의 두 관측 사이에서만 인정한다.** 새 세대의 첫 관측은 기준값만 잡는다. 사용자가 고른 계정을
  이전 활성 기간의 값과 비교해 떠나지 않게 한다. 예외는 자동 전환으로 활성이 된 경우로, 전환 직전 후보 확인의 관측을 새
  세대의 기준값으로 넘겨받고 전환 직후 한 번 바로 조회한다.
- 판정은 순수 함수 `AntigravityExhaustion.evaluate(previous:current:generation:)` 하나가 한다. 활성 계정을 조회하는
  **모든 경로**(5분 폴, 팝오버 게이지, 전환 직후 확인)가 기준값을 바꾸기 전에 이 함수를 먼저 부른다. 비활성 계정
  조회는 기준값만 바꾸고 판정하지 않는다.

**판정.** 같은 세대의 기준값이 0 보다 컸던 모델들 가운데 이번 응답에서 **명시적인 0** 이 된 모델의 집합 M 이 비어
있지 않으면 트리거다. 공유 버킷이 소진되면 그 버킷의 모델이 한 응답에서 함께 0 이 되고, 폴 간격 안에 두 계열이 함께
0 이 될 수도 있으므로, M 에서 하나를 고르지 않고 집합 전체를 쓴다(6회차 두 리뷰어 P1). 값 모름(4.3)이나 행 빠짐은
트리거가 아니다. 그 밖의 0(전이를 보지 못한 0)은 아무것도 하지 않는다.

**기록.** 트리거가 나면 활성 계정에 `RateLimitInfo(modelScoped: true, scopeModelIDs: M, scopeLabel: M 의 계열(둘 이상이면
"Gemini·Claude"), resetsAt: M 의 resetTime 가운데 가장 늦은 것)` 를 기록한다(`mutateFresh`). M 이 모두 풀려야 그 계정이
같은 쓰임으로 다시 후보가 되므로 가장 늦은 값을 쓴다. `scopeModelIDs`·`scopeLabel` 은 옵셔널 새 필드이고 관대한
`init(from:)` 으로 디코드한다(실패 기록 13 대조). `modelScoped: false`(계정 소진)는 Antigravity 에서 쓰지 않으므로
메뉴바 빨간 표시, CLI "한도 소진" 라벨, "모든 계정 한도 소진" 알림은 Antigravity 에 나오지 않는다.

**엔진 규칙(Antigravity 풀).** 엔진은 지금 구조를 쓰고, 아래만 Antigravity 에 한해 바꾼다.
- 떠나기(`onRateLimitHit`, `onTick` 자가복구): 활성 계정의 기록이 **그 계정이 활성이 된 시각 이후**에 쓰였고 아직
  유효할 때만 떠난다. 활성이 된 시각은 `AppState` 가 메모리에 두고 세대 번호가 바뀔 때 함께 갱신한다. 이 조건 안에서는
  핀을 보지 않는다(0절 작성자 결정). 재시작은 활성 시각을 지금으로 바꾸므로 재시작 전의 기록으로는 떠나지 않는다.
- primary 복귀(`onTick` 의 (B)): Antigravity 에서는 하지 않는다. 자동 전환 플래그(`autoSwitchedFromPrimary`)도 세우지
  않는다. primary 는 후보 순서의 맨 앞이므로, fallback 에서 쓰던 모델이 다시 소진될 때 primary 의 그 모델에 여유가
  확인되면 자연히 돌아간다.
- 후보 고르기: 엔진의 후보 선택(`firstAvailable`)에 **제외할 계정 ID 집합**을 넘기는 인자를 더한다. Antigravity 에서는
  엔진 내장 `avoidModelLimited` 필터를 쓰지 않고, `AppState` 가 다음을 모아 넘긴다. 모두 **모델 ID** 로 비교한다.
  - M 과 겹치는 `scopeModelIDs` 의 기록이 아직 유효한 계정
  - 메모리 후보 제외(아래)에서 M 의 모델 하나라도 걸린 계정, 확인 불가 쿨다운 중인 계정
- 갈 곳이 없으면 머문다(`.none`). 후보가 모두 M 의 명시적인 0 으로 확인됐으면 알린다: "모든 Antigravity 계정에서
  <모델 표시명> 한도가 찼어요. <가장 이른 리셋> 이후 다시 쓸 수 있어요." 같은 (모델 집합, 가장 이른 리셋)에 한 번만
  알린다. 확인할 수 없어서 빠진 후보가 있으면 알리지 않는다.
- 엔진 배선: 떠나기 조건(활성이 된 뒤의 기록, 핀 무시)과 primary 복귀 끄기는 `AutoSwitchEngine` 에 프로바이더별 정책 값
  (`AutoSwitchPolicy`: `ignoresPinForModelLimit`, `returnsToPrimary`, `activeSince` 를 받는 떠나기 판정)으로 넘긴다.
  `AppState.apply` 는 Antigravity 의 `.modelExhausted` 전환에 `autoSwitchedFromPrimary` 를 세우지 않는다.

**후보 확인.** 엔진이 Antigravity 계정으로 전환하라고 결정하면 적용하기 전에 그 후보를 조회한다.
- 후보 응답에 M 의 모델이 **모두** 있고 **모두 명시적으로 0 보다 크면** 전환한다. 같은 계열의 다른 모델 값으로 대신하지
  않는다. 조회 결과는 그 후보의 기준값과 게이지 캐시에도 넣는다.
- M 의 모델 하나라도 명시적인 0 이면 전환하지 않고, 메모리 후보 제외(계정 × 모델 ID → 해제 시각)에 넣는다. 해제 시각은
  그 모델의 resetTime 과 지금 + 10분 가운데 늦은 쪽이다(재확인 하한. 6회차 Claude P2-2).
- 같은 후보는 10분에 한 번만 조회한다. 소진 전환과 자가복구 모두 이 하한을 따른다.
- M 의 모델이 응답에 없거나 값 모름이거나, 조회가 일시 실패했거나(네트워크, 5xx), 확인할 수 없으면(secret 을 찾지 못함, 토큰
  만료) **확인 불가**로 보고 전환하지 않는다. 그 후보에 10분 쿨다운을 둔다. 확인할 수 없는 계정으로 옮기면 그 계정에서
  다시 빠져나올 근거가 없기 때문이다.

**비동기 경합.** 조회는 await 를 거치므로 그사이 상태가 바뀔 수 있다. 결정을 적용하기 전에 아래가 모두 그대로인지 본다.
- 활성 세대 번호
- 라이브 키체인 바이트의 해시(같은 이메일 재로그인, 로그아웃)
- 디스크의 **활성 리비전**: `AccountsFile` 의 옵셔널 새 필드 `activeRevisionByProvider`(프로바이더별 정수). 활성 값을
  바꾸는 모든 저장(앱과 CLI)이 1 늘린다. 확인 직전에 파일을 다시 읽는다. 구버전은 이 필드를 버리므로 다시 읽은 값이
  달라지고 "바뀜"으로 보고 취소한다(안전한 쪽).
- 이 풀의 자동 전환 설정(디스크에서 다시 읽은 값)

- 출발 계정의 소진 기록이 지금 시각 기준으로 아직 유효하고, 그사이 더 새 관측에서 출발 계정의 M 이 0 보다 크게 보이지
  않았는지(6회차 Codex P1-4)

활성 폴과 후보 확인은 await 전에 위 값들을 잡고, 기록하기 직전과 `switchTo` 안에서 대상 스냅샷을 읽고 되저장한 **뒤
라이브 쓰기 바로 앞**에서 다시 확인한다. 하나라도 다르면 기록하지 않고 전환을 취소한다. `switchTo` 에 기대값 인자를
옵셔널로 더하고, 수동 전환은 지금처럼 기대값 없이 부른다.

**공통 틱과 분리.** Antigravity 자동 전환의 조회와 키체인 쓰기는 공통 틱이 기다리지 않는 별도 작업에서 한다. 풀마다
진행 중 작업은 하나만 두고, 끝나지 않았으면 새 작업을 만들지 않는다. 쓰기 자체는 4.1 의 5초 제한을 따른다.

**왕복 차단.** 2.1 미확인 1 이 참이면 이전 계정의 실행 중 세션이 토큰을 갱신할 때 키체인을 되돌리고, reconcile 이
라이브를 따라 활성을 되돌린 뒤 엔진이 다시 전환하는 왕복이 생길 수 있다. 자동 전환으로 떠난 지 6시간 안에 **라이브를 따라간 Antigravity 대사**가 활성을 그
계정으로 되돌아가면, 다시 전환하지 않고 그 계정 기록의 리셋 시각까지 이 풀의 자동 전환을 멈춘다(메모리). 알림은 한 번:
"이전 계정의 agy 세션이 계정을 되돌렸어요. 그 세션을 종료해 주세요. 자동 전환은 HH:mm 에 다시 동작해요."
사용자 자신의 전환(앱 수동 전환, CLI `mobius switch`)은 왕복으로 세지 않는다. 앱 수동 전환은 감시를 내린다
(2026-11-20, 코드 리뷰 1회차 Claude P2-2 반영 때 정함). 사용자가 agy 에서 떠난 계정으로 직접 다시 로그인한 경우는
이전 세션의 되돌림과 구분할 수 없어 왕복으로 센다(알려진 한계).

**알림.** 전환: "Antigravity 계정을 전환했어요(<모델 표시명> 한도). 실행 중인 agy 세션은 다시 시작해야 새 계정이
적용돼요." 계정 소진이라고 쓰지 않는다.

**한계(알려진 것).**
- 실행 중인 세션은 전환을 따라가지 않으므로 자동 전환은 다음에 시작하는 세션부터 효과가 있다.
- 쓰던 모델이 이미 0 인 채 앱을 재시작하거나, 사용자가 그런 계정을 직접 고르면 전이를 볼 수 없어 떠나지 않는다.
  사용자는 수동 전환할 수 있다.
- primary 로 돌아가는 시점은 fallback 의 같은 모델이 다시 소진될 때다. 리셋 직후 바로 돌아가지 않는다.
- 소진된 모델이 `remainingFraction` 없이 온다면(2.1 미확인 3) 자동 전환은 조회만 하고 한 번도 전환하지 않는다. 4.3 의
  "값 모름" 로그로 알아보고, 7절 E2E 에서 한 버킷을 실제로 소진시켜 형식을 확인한 뒤 해석 규칙과 fixture 를 정한다.

### 4.8 UI 와 CLI

- 팝오버 탭, 전체 탭 섹션, 설정의 설치 현황 탭에 "Antigravity" 를 더한다. 지금의 카드·탭 구조를 그대로 쓴다(0절).
- 계정 추가는 Codex 와 같은 안내 팝오버를 쓴다: "터미널에서 `agy` 를 실행해 로그인하면 자동으로 등록돼요. 다른
  계정을 더하려면 agy 에서 로그아웃한 뒤 그 계정으로 로그인하세요."
- 자동 전환 토글은 다른 풀과 같은 자리에 둔다. 미리 전환(advisory) 하위 옵션은 Claude 전용이라 보이지 않는다.
- 게이지는 4.3 의 버킷 줄(Gemini, Claude)이다.
- 설치 현황은 agy 바이너리 위치를 `ToolInventory.locateCLI` 로 찾는다(실패 기록 15).
- 형제 코드: `AppState.engines` 에 `.antigravity` 를 더한다(빠지면 `engines[provider]!` 가 틱마다 멈춘다). CLI
  `makeContext` 의 Switcher 에 agy 어댑터를 등록한다. CLI 도움말과 오류 문구의 「claude 또는 codex」, `en.lproj`·
  `ja.lproj` 의 새 문구, README 「알아두면 좋은 제약」과 CLI 계약을 고친다.
- CLI `list`·`status` 는 인자가 없으면 지금처럼 전 풀을 보이고, `auto` 의 기본 풀은 지금처럼 Claude 다.
- CLI `list`·`status` 는 **어느 풀의 변경도** 디스크에 저장하지 않는다(라이브 신원은 메모리에만 반영해 보인다. 2026-11-20 코드 리뷰 4회차에서 Antigravity 에서 모든 풀로 넓힘 — 오래된 목록으로 다른 프로세스가 추가한 계정을 덮지 않게).
  그래서 앱의 Antigravity 대사가 라이브를 따라간 변경을 직접 커밋한 것으로 보고 왕복 차단을 판정할 수 있다. 디스크 활성이
  잠시 낡아도 `mobius switch` 는 라이브 바이트의 이메일로 되저장하므로 엉뚱한 프로필에 저장하지 않는다(2026-11-20, 코드
  리뷰 3회차 Claude P2-1 반영 때 정함).

## 7. 검증 계획

제약: 실기 E2E 의 두 계정은 모두 개인 Gmail 로 한다(0절).

1. 단위 테스트(`MobiusCoreTests`):
   - 어댑터: 형태 검증(토큰 필드, RFC3339 소수부 유무), 바이트 이메일 대조, hex 경로
   - `CLIKeychain`: 네이티브 호출 0회(실패·시간 초과), `-i` 길이 가드, 실패 뒤 "모름"
   - 다운그레이드 호환(4.4-6), 복원 함수가 네 진입점에서 같은 결과(자동 전환 꺼짐, 순서 보존, 중복 없음, 삭제 표시)
   - 오류 격리(4.6): 오류를 던지는 어댑터, 응답하지 않는 어댑터
   - 게이지 파서: 값 모름, `tab_*` 제외, 버킷 라벨과 번호
   - 판정(4.7): 같은 세대 안의 전이만, 새 세대 첫 관측은 기준값, 라이브 해시 변경은 새 세대, 집합 M(공유 버킷 동시 0,
     두 계열 동시 0), 값 모름·행 빠짐은 트리거 아님
   - 후보 확인: M 전체의 명시적 여유, 일부 0 이면 제외(해제 하한 10분), 행 빠짐·값 모름은 확인 불가, 후보별 조회 하한
   - 엔진 정책: 활성이 된 뒤의 기록만 떠나기, 핀 무시, primary 자동 복귀 없음, "모든 계정 소진" 알림 없음
   - 비동기 재확인: 세대·라이브 해시·디스크 리비전·설정·출발 기록 유효성 각각이 바뀌면 취소
   - 롤백 없음: 키체인 쓰기 성공 + 저장 실패에서 키체인 호출이 더 없음
   - fetch 의 전송 경로·UA 단언, client secret 실행 중 읽기(후보 탐색, 실패 시 갱신 없음)
2. 격리 환경: `InMemoryKeychain` 과 임시 `MOBIUS_HOME` 으로 Switcher 왕복.
3. 빌드: `swift build`, `swift test`, `Scripts/make-app.sh`. 저장소에 CI 가 없으므로 결과를 PR 테스트 절에 적는다.
4. 실기 E2E(개인 Gmail 두 개):
   1. 시작 전에 Mobius 와 agy 키체인에 개인 계정만 있는지 확인한다.
   2. 두 계정 등록(adopt), 전환 왕복, 새 agy 세션의 신원과 `credential-user-scope`(2.1 미확인 2).
   3. 이전 세션의 access 토큰 만료 뒤 키체인 되돌림 여부(2.1 미확인 1).
   4. 팝오버 게이지가 두 계정 모두 표시되는지, 한 시간 뒤 비활성 계정 게이지가 갱신되는지(secret 실행 중 읽기).
   5. 자동 전환 토글을 켜고 폴링 조건(최근 사용, 활성 하나)이 지켜지는지 로그로 확인.
   6. 소진 응답 형식(2.1 미확인 3): 한 계정의 한 버킷을 실제로 소진시켜 응답을 기록하고(값은 가리고 구조만), 자동 전환이
      일어나는지 본다. 사용자 계정의 할당량을 쓰는 일이라 진행 전에 사용자에게 묻는다.
